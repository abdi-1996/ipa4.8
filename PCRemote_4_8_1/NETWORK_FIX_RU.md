# PC Remote 4.6.2 — исправление подключения LAN / Tailscale

В 4.6.2 сетевой клиент iPhone переделан архитектурно.

## Главное изменение

Запросы PC Remote к Windows Server больше не выполняются через `URLSession`.
Вместо этого приложение использует `Network.framework` (`NWConnection`) и HTTP/1.1 поверх TCP.
Это убирает зависимость основного транспорта от App Transport Security (ATS), которая блокировала
`http://100.x.x.x:8765` на новых версиях iOS.

## Дополнительная страховка

В `Info.plist` всё равно оставлены ATS-исключения для:

- Tailscale: `100.64.0.0/10`;
- текущего ПК: `100.105.141.17`;
- домашней сети: `192.168.0.0/16` и текущего `192.168.8.248`;
- других частных LAN-диапазонов `10.0.0.0/8` и `172.16.0.0/12`;
- MagicDNS `*.ts.net`.

GitHub Actions после сборки проверяет, что эти значения реально находятся внутри готового `.app`,
и отдельно проверяет, что `APIClient.swift` больше не выполняет PC Remote HTTP через `URLSession`.

## Как проверить вне дома

1. На ПК запустить PC Remote Server и Tailscale.
2. На iPhone включить Tailscale.
3. Выключить Wi‑Fi и оставить 5G.
4. В PC Remote выбрать `Tailscale`.
5. Адрес: `100.105.141.17`, порт: `8765`.
6. Ввести пароль PC Remote Server.

Если Safari по адресу `http://100.105.141.17:8765/api/status` показывает `Unauthorized`, маршрут Tailscale работает.
После установки 4.6.2 приложение должно использовать тот же маршрут через `Network.framework`.
